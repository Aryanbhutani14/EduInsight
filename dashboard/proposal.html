Project Proposal & Literature Survey

The academic case for EduInsight — what gap it addresses, what it sets out to deliver, how it's built, and the prior work it builds on.

Problem Statement

The rapid growth of online education has resulted in a large volume of educational content being generated and stored in the form of lengthy video lectures. Although these recordings provide students with flexible access to learning material, extracting meaningful information from large collections of lecture videos is time-consuming. Students may need to repeatedly watch lectures to locate important concepts, definitions, examples, formulas, explanations, and examination-relevant topics.

The proposed EduInsight system aims to develop a Big Data Analytics framework for processing and analyzing large collections of educational video lectures. The system will transform unstructured lecture data into structured information and perform analytics to identify important topics, concepts, lecture segments, and examination-relevant content. These analytical results will then be used to identify examination-relevant topics and probable question areas, and to rank lecture content by how closely it matches a given topic.

The primary focus of EduInsight is therefore not simply video summarization, but large-scale educational data analysis, where multiple lectures can be processed, compared, aggregated, and analyzed to discover meaningful patterns that are difficult to obtain by manually examining individual videos.

Objectives and Outcomes

  1. Ingest a large-scale lecture corpus into distributed storage — load course, video-caption, and concept metadata into HDFS so downstream processing is genuinely distributed.
  2. Build a distributed NLP preprocessing pipeline — Chinese tokenization (jieba) and stopword removal as a Spark job over caption text, informed by a real data-quality finding.
  3. Generate multilingual content embeddings — one vector per lecture via a multilingual sentence-transformer, so an English query matches Chinese lecture content directly, without translating the corpus.
  4. Cluster lectures and detect redundancy — group lectures by topic similarity and surface concrete cases of overlapping coverage across different courses.
  5. Build a measurable ranking engine — given a student query (e.g. "dynamic programming"), return a ranked list of lectures scored by similarity and concept overlap, with the score shown, not hidden.

Outcomes targeted:

  • A working, reproducible Hadoop/Spark pipeline (not a single-machine script) verified against real data at each stage.
  • A query → ranked-results demo usable in a live presentation.
  • A documented, honest account of data-quality issues found and how they were handled.

Methodology

Four phases, each one building on the results of the last.

Phase 1Data Acquisition & Verification

Get the raw lecture data from its source and confirm it is complete before using it.

  1. Download the source data

    Course records, lecture captions, and topic tags are downloaded from MOOCCubeX, a Tsinghua University lecture dataset, using direct HTTPS transfer.

  2. Validate every record

    A Python script parses each of the 59,581 lecture records as JSON to catch missing or corrupted data before it enters the pipeline.

  3. Bridge courses to videos

    Courses and videos use separate ID systems with no official link between them; the missing mapping file is located and used to connect every video back to its course.

Phase 2Development Dataset & Analysis

Work on a smaller, faster slice of the data first, to design and test the system before scaling up.

  1. Build a working subset

    Computer Science courses with enough usable lecture content are filtered out in Python, forming a ~4,000-video development set.

  2. Explore the data

    Video length, caption density, and topic coverage are analyzed with Python to guide every design decision that follows.

Phase 3Distributed Storage Setup

Store and process lecture data at scale, using infrastructure built for large datasets, not a single machine.

  1. Set up the Linux environment

    Ubuntu (via WSL2) is installed as the operating environment, with Apache Hadoop and Apache Spark configured on top of it.

  2. Load data into HDFS

    The dataset is uploaded into HDFS (Hadoop Distributed File System), Hadoop's storage layer built to hold large data reliably across a cluster.

  3. Verify with Spark

    Apache Spark reads the data directly from HDFS and confirms every record matches the source — proving storage and processing work together, not just separately.

Phase 4Content Analysis & Ranking

Turn raw lecture text into something searchable, comparable, and rankable by topic.

  1. Segment the text

    Chinese captions are split into words using jieba, a Chinese language tokenizer, with filler words removed via a stopword list.

  2. Embed each lecture's meaning

    A multilingual sentence-transformer model converts each lecture into a numeric vector, so an English search term can match Chinese content directly.

  3. Cluster similar lectures

    Spark MLlib's K-Means groups lectures with similar vectors, surfacing overlapping content across different courses.

  4. Rank by relevance

    Lecture vectors are compared to a query vector using cosine similarity, ranking results by how closely they match.

System architecture

Data flows bottom → top: raw files land in HDFS, Spark processes them, ML methods extract meaning, and the application layer serves ranked results.

The gap these six papers leave open: Papers 1–2 provide data but no recommendation system; Paper 3 proposes a video big-data architecture conceptually but never implements one; Paper 4 recommends concepts from user history, not lectures ranked by topic match; Paper 5 surveys the field but builds nothing; Paper 6 supplies the embedding technique but needs multilingual extension. EduInsight is an implemented system combining these pieces — genuine Hadoop/Spark processing, at MOOC scale, doing cross-course content ranking none of the six attempts together.
